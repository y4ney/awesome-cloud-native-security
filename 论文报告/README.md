## 2020-09

1. 了解 Docker Hub 的安全风险

    - 📅 日期：2020-09-14
    - 📑 文件：[Understanding the Security Risks of Docker Hub](./2020-09/Understanding%20the%20Security%20Risks%20of%20Docker%20Hub.pdf)
    - 🔗 链接：<https://nesa.zju.edu.cn/download/Understanding%20the%20Security%20Risks%20of%20Docker%20Hub.pdf>
    - 💬 简介：Docker 因其提供可直接由宿主机内核运行的高效容器而日益普及。Docker Hub 是最流行的 Docker 镜像仓库之一，数百万个镜像已被下载数十亿次。然而，在过去几年中，一些利用这一关键镜像分发渠道的高调攻击事件频频发生。目前，这一新兴生态系统带来的安全风险尚不明确。本文通过首次大规模分析，揭示、描述并理解了 Docker Hub 的安全问题。首先，我们通过经验性但全面的分析，揭示了 Docker 镜像的多个安全关键方面，涵盖了运行命令中的敏感参数、Docker 镜像中执行的程序以及包含软件中的漏洞。其次，我们对 Docker 镜像进行了大规模且深入的安全分析。我们从 Docker Hub 收集了 2,227,244 个 Docker 镜像及其相关的元信息。该数据集使我们能够发现许多富有洞察力的结论。 （1）使用敏感参数运行命令会对用户和主机造成灾难性危害，例如主机文件和显示内容泄露，以及对主机发起拒绝服务攻击。（2）我们发现了 42 个恶意镜像，这些镜像可能导致远程代码执行和恶意加密货币挖矿等攻击。（3）Docker 镜像中软件的漏洞修补严重滞后，甚至被忽略。我们认为，我们的测量和分析是对 Docker Hub 安全问题的重要初步研究，并呼吁未来致力于保护新的 Docker 生态系统。

## 2019-11

1. 胡迪尼的逃脱：打破Linux控制组的资源控制

    - 📅 日期：2019-11-11   
    - 📑 文件：[Houdini’s Escape: Breaking the Resource Rein ofLinux Control Groups](./2019-11/Houdini’s%20Escape-%20Breaking%20the%20Resource%20Rein%20of%20Linux%20Control%20Groups.pdf)
    - 🔗 链接：<https://gzs715.github.io/pubs/HOUDINI_CCS19.pdf>
    - 💬 简介：Linux 控制组（即 cgroups）是实现操作系统级容器化的核心基础组件。cgroups 机制将进程划分为分层管理的组，并通过各类控制器对 CPU、内存、块设备 I/O 等系统资源进行精细化管控。新创建的子进程会自动从父进程继承 cgroups 属性，以此保障资源管控的执行。遗憾的是，通过进程创建继承的 cgroups 限制，并不能始终保证资源计量的一致性与公平性。本文设计了一系列利用策略：通过将进程与原所属进程组解除关联，制造 “带外负载”。这类负载所消耗的系统资源，不会被计入对应的 cgroups 配额中。为进一步验证该方法的可行性，我们基于 Docker 容器给出五个典型案例，展示在真实场景中如何突破 cgroups 的资源限制。更严重的是，在多租户容器环境中，攻击者可利用这些 cgroups 设计缺陷，让恶意容器大幅超额占用资源，显著拖慢同一宿主机上的其他容器，并在系统资源竞争中获取不正当优势。我们在本地测试平台与亚马逊 EC2 云专属服务器上开展了大量实验。结果表明：恶意容器可将 CPU 等系统资源消耗放大至配额上限的 200 倍，并使同主机其他容器中特定任务的计算与 I/O 性能下降95%。
